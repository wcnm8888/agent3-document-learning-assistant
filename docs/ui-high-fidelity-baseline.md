## 审计结论

当前实现已经具备深色主题、三栏容器、文档库入口、来源/笔记入口和详情入口，但页面仍然呈现为“原有 Gradio 表单和面板的深色适配”。Figma 设计稿要求的是“知识工作台外壳 + 独立主工作区 + 上下文检查器”，两者在宏观结构上仍有明显差异。

因此，本项目 UI 状态应区分为：

1. 业务能力：已完成；
2. UI-R4/UI-R5 原阶段功能性实现：已完成；
3. Figma 高保真视觉与交互落地：待完成；
4. UI-R6/UI-R7：应在高保真实现完成后作为最终回归门禁，不应替代高保真实现。

## Figma 实现基线

### 桌面端 1440×900

- 全局画布使用黑色背景，顶部区域约 76px 高。
- 左侧空间导航目标宽度约 200～220px，菜单项高度约 42px。
- 中间是主任务区，学习会话保持稳定的阅读宽度；文档库页面使用更宽的列表工作区。
- 右侧上下文检查器承担来源、笔记和文档详情，不与主任务区争夺同等视觉权重。
- 问答 Composer 固定在主工作区底部，目标高度约 68px。
- 用户消息使用蓝色气泡，助手消息使用深灰表面，来源和笔记使用可扫描卡片。

### 平板端 1024×768

- 左侧导航收缩为图标或菜单入口。
- 主工作区优先保持可读宽度。
- 文档详情和上下文检查器可以使用抽屉或下移面板。
- 不允许通过压缩所有列来保留桌面三栏。

### 移动端 390×844

- 顶部只保留菜单、品牌和当前范围。
- 主内容按学习任务顺序展示：会话 → Composer → 来源/笔记入口。
- 来源和笔记使用底部面板；文档详情使用全屏抽屉或确认弹窗。
- 列表仅保留文档名、格式、状态和更新时间；完整 metadata 进入详情。

## 业务语义保护

- 不改变 `document_id`、`content_hash`、`chunk_id` 或 `source_locator`。
- PDF 来源继续显示页码；Markdown 来源继续显示章节、段落和行号。

- 会话、笔记、引用、归档、恢复、删除和重新索引继续复用现有服务语义。
- 不修改解析、分块、Embedding、Qdrant、SQLite Schema 或现有 points。
