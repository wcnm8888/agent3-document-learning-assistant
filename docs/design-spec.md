# UI 设计规格

> **最终视觉与实现权威（UI-REC4，2026-08-04）**：UI-REC2 学习会话、UI-REC3 文档库和 UI-REC4 移动上下文/文档详情均已获负责人批准。样式唯一权威为 `src/doc_qa/ui.css`。UI-REC0～UI-REC4 已全部完成，本轮 UI 高保真恢复任务正式收口；没有 UI-REC5。

## UI-REC4 移动上下文视觉契约

- 390×844 以单任务主工作区为底层，导航使用 44px 菜单入口；来源/笔记通过底部面板访问，不压缩为三栏桌面布局。
- 来源/笔记面板固定贴底，高度 390px、顶部圆角 20px；标题、关闭按钮和 44px Tab 为稳定首层。来源卡使用真实引用数据，PDF 只显示页码，Markdown 只显示章节、段落和行号。
- 笔记 Tab 继续使用现有保存/更新回调与当前会话隔离；成功和失败必须有文字。文档详情使用接近全屏的内部滚动面板，并保留完整标识、统计和生命周期操作。
- 1024×768 保留 300px 上下文检查器和按钮式菜单入口；桌面学习会话与文档库继续使用已批准基线。三种视口禁止页面级溢出，主要触控目标不得小于 44px。

## UI-REC3 文档库视觉契约

- 桌面主工作区按“标题与真实上传/索引入口 → 搜索和紧凑筛选 → 全部文档列表”组织，不使用纵向原生表单作为首级视觉。
- 文档行展示名称、格式、文字状态和紧凑更新时间；长文件名截断，完整元数据进入右侧检查器。
- 默认文档和用户选择必须有明确边框、`aria-pressed` 与键盘焦点；选择行为必须更新真实 Gradio 详情状态。
- 右侧检查器显示完整 `document_id`、hash、格式、统计、定位方案、更新时间、脱敏错误和既有生命周期入口；只有删除使用危险色。
- 由于当前产品是“选择文件 → 开始索引”两步业务，允许相对 Figma 的单上传按钮保留等效的第二步操作；不得伪装成一键完成。
- 1024×768 和 390×844 本阶段仅做结构回归；移动端上下文高保真属于后续阶段。

## UI-REC2 学习会话视觉契约

- 标题区只保留页面语义、简短说明、真实问答范围、文字就绪状态和蓝色“新会话”；不暴露完整 `session_id`，不重复范围信息。
- 时间线使用“今天 · 学习记录”分隔；用户问题为蓝色气泡，助手回答为独立深色卡片；来源数量和笔记提示是回答卡片二级操作。
- 时间线占据标题区与 Composer 之间的弹性空间并内部滚动；空态只提供一组简短引导，不生成额外范围卡或固定大卡。
- Composer 是主工作区底部的一体式输入面：输入、蓝色提交、低权重清空及键盘提示共用一个边界，桌面完成态高度约 93px。
- 1440×900 以固定视口完成高保真验收；1024×768 与 390×844 在本阶段仅承担结构回归，不扩展为移动端上下文高保真实现。
- 所有内容来自真实回调或确定性安全夹具；不得用静态答案、来源、笔记或成功状态替代业务数据。
- 负责人反馈校准基线：面板和胶囊不使用投影/外发光；中文正文优先使用 `Inter`/`Noto Sans SC`/`Microsoft YaHei UI` 系统回退并启用抗锯齿；用户与回答卡使用统一 14px 圆角，不再使用方向性尖角；最近文档采用紧凑平面行，只有当前首项使用弱表面。
- 右侧检查器固定为 368px 桌面宽度，按“上下文标题 → 来源/笔记 Tab → PDF/Markdown 来源卡 → 学习笔记预览 → 当前范围”组织；来源定位继续来自真实 `source_locator`，不复制或伪造数据。

## UI-REC1 布局契约

- 桌面：顶部栏；216px 左侧导航；`minmax(0, 1fr)` 主工作区；340px 右侧检查器。
- 平板：导航收缩为可打开入口；主任务保持可见；上下文区域保持独立边界。
- 移动：单主任务面；导航使用左侧抽屉；来源/笔记使用底部面板。
- 纵向策略：核心工作区固定于视口，时间线、文档列表和检查器各自在内部滚动；Composer 不随空状态无限下沉。
- 数据策略：所有展示继续绑定真实控制器回调；不得用静态文档、答案、来源或笔记替代业务数据。
- 等效实现：允许因 Gradio DOM 结构使用视觉包装，但不得改变 `document_id`、`source_locator`、PDF 页码或 Markdown 章节/段落/行号语义。

# 历史 UI 规格与实现记录（非权威）

## HF-R4 来源、笔记与响应式检查器规格（2026-08-03）

检查器的主视觉只使用受控 HTML 卡片：来源 Tab 的卡片首行是格式标签（PDF 紫色、Markdown 蓝色），次行是文档名与对应定位；片段和原始 `source_locator` 通过 `<details>` 二级展开，避免技术定位淹没主阅读路径。PDF 只显示页码；Markdown 只显示章节、段落和行号，不相互伪造。

笔记 Tab 使用当前 `session_id` 的 SQLite 笔记记录渲染紧凑卡片；编辑、保存和更新继续使用既有 Gradio 控件和回调，隐藏的 Dataframe 仅维持兼容输出。空、成功、失败与前置条件均保留文字状态，不能仅靠颜色。

1024×768 将检查器折叠为右侧抽屉，390×844 将其变为底部面板；两者均保留来源/笔记 Tab。移动端面板高度不超过 `min(82vh, 720px)`，保障主工作区仍可见。该阶段不宣称整个页面与 Figma 完成像素级一致，HF-R5 仍需进行并排视觉 QA。

## HF-R3 文档库高保真规格与实现（历史记录）

文档库是独立主工作区，而非纵向表单：桌面端按“标题/说明 + 真实上传与索引入口 → 46px 搜索框 → 42px 筛选工具栏 → 76px 紧凑文档行”组织。上传继续使用真实 Gradio `File` 与原索引回调；由于当前业务仍是“选择文件后索引”的两步流程，视觉上提供“上传文档”和“开始索引”两个明确入口，未伪造成一键索引。

文档行展示文档名、定位单元/分块摘要、格式、带文字的状态和更新时间；长名称最多两行，完整 `document_id`、hash、索引统计、定位方案、更新时间和脱敏错误仅在右侧详情检查器显示。详情选择器只控制检查器，禁止写入或影响 `document_filter`。已索引 PDF 明确显示 `pdf-page-v1`，Markdown 明确显示 `markdown-heading-line-v1`；索引失败文档必须保留其可读元数据并显示脱敏错误详情。

响应式等效：1024px 保持主工作区优先；390px 将工具栏收敛为单列、筛选为两列/一列混合、文档行只呈现名称、状态与更新时间，避免十列表格式的阅读负担。移动端完整详情检查器和来源/笔记底部面板属于 HF-R4，不在 HF-R3 宣称完成。

## HF-R1 外壳实现基线（2026-08-03）

HF-R1 将视觉契约落到唯一工作台根：1440×900 使用 216px 左侧空间导航、760px 中间主区、368px 右侧检查器和 24px 栏间距；顶部栏高 76px。1024×768 收敛为导航 + 主区两列，检查器移至主区之后；390×844 保留菜单收缩入口。导航说明必须位于导航组之后，不能参与导航项栅格；会话首级状态只能显示短文本，完整 `session_id` 保留在状态对象而不显示。

Gradio Markdown 包装层若仅用于元数据 chip，必须由父级管理宽度并禁用默认 `overflow:auto`；文档库标题元数据、搜索输入和任何短状态都不得出现水平滚动条。HF-R1 只定义外壳与 P0 结构，不把当前时间线、Composer、文档工具栏或来源/笔记默认结构视为已完成的高保真组件。

## HF-R0 权威视觉契约（2026-08-03）

Figma Review v1 是当前 UI 视觉验收基线，不是仅供配色参考的灵感图。桌面端必须呈现唯一的 1160～1200px 工作台根容器：56～64px 顶栏、168～192px 左侧空间导航、可伸缩的中间主工作区、280～304px 右侧检查器，栏间距为 16～24px。中间工作区优先；导航、会话和检查器不得作为三个同权重面板。

学习会话按“标题/说明与短状态 → 真实消息时间线 → 一体式底部 Composer”组织；完整 session ID 只在二级详情展示，不能产生横向滚动。文档库按“标题与上传 → 搜索/筛选工具栏 → 紧凑真实文档行 → 当前选择文档的右侧详情”组织。来源/笔记使用显式 Tab：PDF 保留页码，Markdown 保留章节、段落、行号。平板收缩导航和检查器，移动端使用菜单、单主工作区和来源/笔记底部面板。

以上内容不得改变 `document_id`、`source_locator`、PDF/Markdown 定位、document_filter、会话隔离、笔记关联或生命周期业务语义。空、加载、成功、失败和禁用状态必须有文字表达；高保真允许对原生组件做受控视觉包装，但不得伪造业务数据。完整契约与可接受的等效边界见 `docs/project-management/ui-fidelity-recovery-task-card.md`。

## UI-2 Design System 与核心页面规格

> 本节是当前 UI 美化任务的设计规格，覆盖并替代旧的“浅色内容面板、橙色主操作”视觉建议；旧内容保留为历史实现基线。完整任务边界和 UI-0～UI-5 阶段地图见 `docs/project-management/ui-beautification-task-card.md`。

### 视觉方向

- 产品气质：深色知识工作台、克制、专注、可核验、适合长时间阅读。
- 页面结构：文档库 → 学习会话 → 来源/笔记，桌面端三栏，窄屏使用抽屉或可展开面板。


## 多文档与 Markdown 知识库管理：Phase 1 UI 规格

### 用户流程

```text
打开文档库
  -> 上传 PDF/Markdown
  -> validating
  -> parsing
  -> indexing
  -> indexed / duplicate / failed
  -> 选择文档范围
  -> 创建或恢复当前范围会话
  -> 提问、查看来源、保存笔记
```

### 文档库信息架构

- 上传区：支持 `.pdf`、`.md`、`.markdown`，显示格式校验和文件名；
- 文档列表：文档名、格式、状态、页数或章节/内容单元数、分块数、points、更新时间；
- 当前范围：`全部文档`或指定 `document_id`；范围必须明确显示；
- 来源信息：PDF 显示页码，Markdown 显示章节路径、段落序号和行号；不显示伪造页码；
- 文档操作：第一阶段只支持上传、查看和切换，不提供归档/删除按钮。

### 状态和反馈

| 状态 | UI 行为 |
| --- | --- |
| empty | 显示上传引导和“尚无文档”说明 |
| validating | 禁用重复提交，显示格式/大小校验中 |
| parsing | 显示解析进度和可取消前的明确状态 |
| indexing | 显示 Embedding/Qdrant 索引中，不宣称已完成 |
| indexed | 显示可用文档、来源定位和分块统计 |
| duplicate | 显示已存在的 canonical 文档，不新增 points |
| failed | 显示脱敏错误、失败阶段和重试入口 |
| no_results | 保留问题，明确当前范围没有足够依据 |
| database error | 显示本地数据存储不可用，不伪造文档状态 |
| scope switched | 清空当前回答、来源、待保存笔记和 Prompt 上下文；保留历史记录 |

### 文档切换规则

切换文档或全部文档范围时：

1. 清空当前页面回答和来源；
2. 清空待保存笔记关联；
3. 创建新的当前问答上下文；
4. 后续检索携带新的 `document_id` 或显式 all-documents scope；
5. 旧会话仍可在 SQLite 中恢复，但不自动注入新范围 Prompt。

### 响应式和可访问性

- 1440×900：文档库、对话、来源三栏；
- 1024×768：文档库和来源面板收窄，保留清晰的范围选择；
- 390×844：文档库、对话、来源/笔记纵向排列，来源可折叠；
- 上传、范围选择、状态变化和错误必须有文本反馈；
- 键盘焦点、禁用状态和错误信息不能只依赖颜色；
- 长文件名、长章节路径和长 source_locator 必须换行或折叠，不能横向撑破页面。
