# 当前 UI 与交互设计规格

## 1. 设计目标

当前 UI 是深色本地知识工作台，强调三个连续任务：管理文档、基于文档提问、核对来源并沉淀笔记。设计目标是高信息密度、清晰层级、可追溯来源和稳定响应式行为，而不是通用聊天页面。

冻结视觉基准位于 `docs/assets/ui-visual-baseline/`。该目录中的桌面学习会话、桌面文档库和移动端上下文图是视觉验收基线；业务语义始终以代码和本文件为准。

## 2. 页面信息架构

### 应用外壳

- 顶部品牌栏：产品名称、简短定位、当前范围/本地运行状态；
- 左侧空间导航：文档库、学习会话、来源与笔记、学习报告；
- 最近文档：使用真实文档目录动态渲染；
- 中间主工作区：一次突出一个核心任务；
- 右侧上下文检查器：文档详情，或来源/笔记。

桌面端不是三个同权面板：中间工作区是主任务，左侧用于导航，右侧用于上下文核验。

### 文档库工作区

- 标题与上传主操作；
- 搜索、格式筛选、状态筛选和更新时间排序工具栏；
- 紧凑文档行，展示文档名、格式、状态、更新时间和必要统计；
- 长文件名截断但保留可识别前缀，完整值进入右侧详情；
- 当前选择行有非颜色唯一的选中表达；
- 详情检查器展示完整 `document_id`、hash、定位方案、统计、错误和生命周期入口。

搜索、筛选和排序只改变列表展示，不得改变问答范围。

### 学习会话工作区

- 标题、简短说明、当前问答范围、会话状态和“新会话”主按钮；
- 时间线内部滚动，Composer 固定在工作区底部；
- 用户问题使用蓝色消息气泡；
- 助手回答使用中性回答卡片；
- 来源数量、保存笔记和复制/时间是回答卡片的二级操作；
- 不展示完整 session ID；
- 空状态紧凑，不制造无意义大面积留白。

### 上下文检查器

- 学习会话中使用“来源 / 笔记”Tab；
- 文档库中切换为文档详情和生命周期区域；
- 来源必须来自真实检索结果；
- 笔记必须来自当前会话/回答关联；
- 不使用静态伪内容填充视觉。

## 3. 来源卡片

### PDF

- 文档名；
- `PDF` 类型标签；
- 页码；
- 相似度（如当前数据提供）；
- 来源片段；
- 展开原始引用入口。

### Markdown

- 文档名；
- `MARKDOWN` 类型标签；
- 章节；
- 段落；
- 行号；
- 来源片段；
- 展开原始引用入口。

Markdown 不显示伪造页码。

## 4. 视觉系统

当前 Token 以 `src/doc_qa/ui.css` 的 `:root` 为运行权威：

| Token | 当前值 / 语义 |
|---|---|
| 页面背景 | `#09090b` |
| 主面板 | `#18181b` |
| 次表面 | `#202023` |
| 抬升表面 | `#27272a` |
| 默认边框 | `#303036` |
| 主文字 | `#fafafa` |
| 次文字 | `#a1a1aa` |
| 弱文字 | `#71717a` |
| 主交互 | `#2f80ed` |
| 成功 / 警告 / 错误 | `#22c55e` / `#f59e0b` / `#ef4444` |
| 面板 / 控件圆角 | `12px` / `8px` |
| 面板阴影 | 无 |

字体栈：`Inter`、`Noto Sans SC`、`Microsoft YaHei UI`、`Microsoft YaHei`、`PingFang SC`、sans-serif。中文正文优先系统字体稳定性，不依赖未随项目交付的在线字体。

### 字体层级

- 页面主标题：20–24px，600–700；
- 区块标题：14–16px，600；
- 正文和控件：13–14px；
- 辅助文字：11–12px；
- 标识值使用等宽字体时必须允许复制或在详情中完整显示。

### 组件原则

- 蓝色只承担主要操作、当前导航焦点和用户消息重心；
- 绿色表示成功，但必须同时显示文字；
- 危险删除使用红色边界和确认文案；
- 避免同时叠加大圆角、粗描边、阴影和多层卡片；
- 图标语言统一，不用无语义 Unicode 符号冒充图标；
- 禁用、加载、错误和选中状态均需有文字或形状表达。

## 5. 响应式契约

### 桌面：1440×900

- 顶栏、左侧导航、中间工作区和右侧检查器在首屏形成稳定框架；
- Composer 完整可见；
- 时间线和长列表使用区域内滚动，不让全页面承担主滚动；
- 无横向溢出和组件重叠。

### 平板：1024×768

- 保留主工作区优先级；
- 左侧导航可收缩；
- 文档详情或上下文检查器可通过抽屉/收缩面板访问；
- 不允许三栏强行等宽挤压主工作区。

### 移动：390×844

- 顶部提供明确的导航入口；
- 文档库、学习会话、来源/笔记仍可切换；
- 来源和笔记使用底部面板；
- 文档详情使用全屏抽屉或等效移动容器；
- 删除使用明确确认弹窗/区域；
- 不展示不可读的多列表格；
- 主要触控目标至少约 44px。

样式只使用现有三个媒体规则：桌面基线、`max-width: 1100px`、`max-width: 760px`，另保留 reduced-motion 可访问性规则。

## 6. 状态规范

必须覆盖：初始化、空知识库、上传、校验、解析、索引、成功、重复、失败、无搜索结果、无检索结果、回答生成、回答成功、问答失败、外部服务不可用、数据库错误、笔记前置条件、保存成功/失败、归档、删除确认/失败、恢复和文档范围切换。

每个状态必须：

- 有明确文字；
- 不只依赖颜色；
- 错误信息脱敏；
- 加载期间避免重复提交；
- 不伪造成功、答案、来源、笔记或文档。

无法安全真实复现的故障可通过 UI 边界故障注入或测试替身验证，但必须记录验证方式。

## 7. 交互与业务保护

- `document_filter` 是问答范围唯一入口；
- 文档范围切换清空当前回答、来源和待保存笔记；
- 新会话创建新的隔离 session；
- 文档切换不串用笔记或引用；
- PDF 页码与 Markdown 章节/段落/行号语义不变；
- 归档、删除、恢复继续调用既有生命周期服务；
- 删除必须确认，失败不能显示成功；
- 完整 `document_id`、hash 和错误详情只在详情区完整展示，避免破坏窄屏布局。

## 8. 可访问性

- 主要控件有可理解标签；
- 键盘焦点使用高对比轮廓；
- 文字与背景保持基本可读对比；
- Tab 选中、禁用、危险和成功状态不只靠颜色；
- 支持 reduced motion；
- 表格/文档行与详情的关系应可理解；
- 错误信息不得包含 API Key、Token、cookie 或内部敏感值。

## 9. 实现约束

- `src/doc_qa/ui.css` 是唯一运行时 CSS 权威；
- 不在 `ui.py` 恢复多代内嵌 CSS；
- 修改现有规则应原位合并，不添加 `final`、`fix`、`override` 等阶段尾部补丁；
- Gradio 原生组件可以被视觉包装或隐藏默认外壳，但必须继续绑定真实回调；
- 不新增重量级前端依赖；
- 不因 UI 改造修改解析、RAG、Embedding、Qdrant、SQLite schema 或生命周期业务逻辑。

## 10. 已知 UI 风险

- Gradio DOM 和 CSS 选择器可能随上游版本变化；
- `upload_progress?upload_id=undefined` 404 是独立非阻塞风险，未在 UI 任务中关闭；
- 浏览器视觉验收必须固定视口、100% 缩放和确定性数据状态；
- 自动化功能测试不能替代与冻结基准的人工并排视觉审核。
