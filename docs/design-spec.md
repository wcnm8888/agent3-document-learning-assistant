# UI 设计规格初稿

> 本文件包含原单 PDF 产品的 Phase 5 UI 基线和当前多文档任务的 Phase 1 UI 规格。原 Phase 5 内容属于历史基线；当前多文档任务 Phase 2 未修改 UI，活动状态以 `docs/project-management/current-task.md`、`roadmap.md` 和 `implementation-plan.md` 为准。

## 参考策略

- ChatGPT UI Kit：参考应用外壳、侧边栏、会话、文档库和设置的信息结构。
- AI Chatbot UI：参考核心问答页、推荐问题、空状态和简洁视觉。
- 不直接复制模板的业务内容、品牌、组件代码或完整页面。

## 页面结构

- 左侧：知识库、文档、会话和笔记入口。
- 中间：对话流、问题输入、推荐问题和回答状态。
- 右侧：来源引用、检索片段、相似度和当前文档信息。
- 抽屉/面板：笔记、学习统计和报告。

## 必须覆盖的状态

初始化、加载中、空知识库、上传中、解析失败、索引失败、无相关内容、回答生成中、回答成功、引用展开、保存笔记成功、外部服务不可用。

## 响应式验收

1440×900、1024×768、390×844；移动端右侧来源面板改为抽屉或底部面板。

## Phase 5 实际实现（历史基线）

- 视觉方向：白色内容面板、浅灰页面背景、蓝色信息强调、橙色主操作按钮；保持参考模板的信息层级，但未复制模板组件或品牌内容。
- 1440×900：文档库、学习会话、来源与复习三栏并列；统计与报告位于底部折叠区域。
- 1024×768：面板内边距和聊天区高度收缩，三栏仍保持可用。
- 390×844：三栏折叠为纵向顺序，文档库优先，问答居中，来源与复习后置，满足移动端阅读顺序。
- 已验证状态：初始化空状态、索引处理中、索引成功、回答成功、来源展开、笔记保存成功、笔记更新成功、新会话空状态和统计报告。
- 失败与校验状态由服务层错误转换为脱敏 UI 状态：非 PDF、索引失败、问答失败、笔记校验失败和数据库错误均不显示 API Key 或 token。

## 多文档与 Markdown 知识库管理：Phase 1 UI 规格

### 用户流程

```text
打开文档库
  -> 上传 PDF/Markdown
  -> validating
  -> parsing
  -> indexing
  -> indexed / duplicate / failed
  -> 选择文档范围
  -> 创建或恢复当前范围会话
  -> 提问、查看来源、保存笔记
```

### 文档库信息架构

- 上传区：支持 `.pdf`、`.md`、`.markdown`，显示格式校验和文件名；
- 文档列表：文档名、格式、状态、页数或章节/内容单元数、分块数、points、更新时间；
- 当前范围：`全部文档`或指定 `document_id`；范围必须明确显示；
- 来源信息：PDF 显示页码，Markdown 显示章节路径、段落序号和行号；不显示伪造页码；
- 文档操作：第一阶段只支持上传、查看和切换，不提供归档/删除按钮。

### 状态和反馈

| 状态 | UI 行为 |
| --- | --- |
| empty | 显示上传引导和“尚无文档”说明 |
| validating | 禁用重复提交，显示格式/大小校验中 |
| parsing | 显示解析进度和可取消前的明确状态 |
| indexing | 显示 Embedding/Qdrant 索引中，不宣称已完成 |
| indexed | 显示可用文档、来源定位和分块统计 |
| duplicate | 显示已存在的 canonical 文档，不新增 points |
| failed | 显示脱敏错误、失败阶段和重试入口 |
| no_results | 保留问题，明确当前范围没有足够依据 |
| database error | 显示本地数据存储不可用，不伪造文档状态 |
| scope switched | 清空当前回答、来源、待保存笔记和 Prompt 上下文；保留历史记录 |

### 文档切换规则

切换文档或全部文档范围时：

1. 清空当前页面回答和来源；
2. 清空待保存笔记关联；
3. 创建新的当前问答上下文；
4. 后续检索携带新的 `document_id` 或显式 all-documents scope；
5. 旧会话仍可在 SQLite 中恢复，但不自动注入新范围 Prompt。

### 响应式和可访问性

- 1440×900：文档库、对话、来源三栏；
- 1024×768：文档库和来源面板收窄，保留清晰的范围选择；
- 390×844：文档库、对话、来源/笔记纵向排列，来源可折叠；
- 上传、范围选择、状态变化和错误必须有文本反馈；
- 键盘焦点、禁用状态和错误信息不能只依赖颜色；
- 长文件名、长章节路径和长 source_locator 必须换行或折叠，不能横向撑破页面。

### Phase 1 设计边界

本节记录 Phase 1 的 UI 规格；Gradio 组件、事件处理和浏览器验收已在后续 Phase 4 实现补充中完成。

## 方向 B：文档生命周期 UI 规格（设计阶段）

- 文档详情展示状态、内容哈希短值、point 计数、最后错误和最近操作；默认列表过滤 deleted。
- 归档/恢复为可逆按钮；删除按钮必须展示文档名、document_id、points 数和“历史笔记/来源保留”的二次确认。
- deleting/inconsistent 显示不可操作状态和明确恢复建议，不显示“删除成功”。PDF 继续显示页码，Markdown 继续显示章节/段落/行号。

## 方向 C：知识库可用性 UI 规格（待实现）

- 文档搜索按名称/短 document_id，格式和状态为独立筛选，更新时间降序且可切换排序。
- 搜索/筛选只影响文档库展示，不修改当前会话范围；切换范围仍清空临时回答、来源和待保存笔记。

### Phase 4 实现补充（2026-08-01）

- 实际页面采用文档库、学习会话、来源与复习三栏结构；移动端折叠为文档库、问答、来源/笔记纵向顺序。
- 上传组件支持 PDF/Markdown；文档表展示格式、短 document_id、索引状态、页数或 Markdown 单元数、分块、points 和定位方案。
- 范围切换由 `DocumentScopeState` 驱动，清空当前回答、来源、待保存笔记和临时上下文，保留 SQLite 历史数据。
