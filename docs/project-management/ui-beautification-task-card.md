## UI-2 设计系统

### 视觉关键词

克制、专注、可核验、信息密度适中、适合长时间阅读。避免装饰性渐变、玻璃拟态和与文档任务无关的产品入口。

### 颜色 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `bg-canvas` | `#09090B` | 页面背景 |
| `surface-1` | `#18181B` | 主面板 |
| `surface-2` | `#202023` | 输入区、嵌套区 |
| `surface-3` | `#27272A` | 浮层、选中项、强调卡片 |
| `border` | `#3F3F46` | 常规边框 |
| `border-subtle` | `#27272A` | 弱分隔线 |
| `text-primary` | `#F4F4F5` | 标题和主要内容 |
| `text-secondary` | `#A1A1AA` | 辅助说明 |
| `text-muted` | `#71717A` | 弱提示和次要元数据 |
| `action-primary` | `#2F80ED` | 主要按钮、链接、选中状态 |
| `action-primary-hover` | `#2563EB` | 主交互悬停 |
| `success` | `#22C55E` | 完成和可用 |
| `warning` | `#F59E0B` | 警告、风险和需要注意 |
| `danger` | `#EF4444` | 删除、失败和危险操作 |
| `disabled` | `#52525B` | 禁用控件 |

橙色不再作为普通主按钮颜色，只用于警告或高注意状态。颜色不能是状态的唯一表达方式，必须同时有文字、图标或结构变化。

### 字体和排版

- 中文优先使用系统字体：`Microsoft YaHei`, `PingFang SC`, `Noto Sans CJK SC`, `sans-serif`。
- 不引入 Figma 的 Satoshi 或其他外部字体依赖。
- 页面标题：24px / 32px / 600。
- 区域标题：16px / 24px / 600。
- 正文和问答：14px～16px / 22px～24px。
- 表格正文：13px～14px / 20px。
- 辅助说明和元数据：12px～13px / 18px。
- 长来源片段正文不低于 14px；不使用随视口缩放的字号。

### 间距、圆角和层级

- 基础间距单位：4px；常用间距为 8、12、16、20、24、32px。
- 页面内边距：桌面 24px，平板 16px，移动端 12px。
- 面板圆角：10px；控件圆角 8px；标签和状态胶囊 999px。
- 边框优先于阴影表达分层；阴影仅用于浮层和抽屉。
- 面板阴影使用低透明度黑色，不使用彩色发光。
- 同一层级的卡片不重复嵌套大量边框。

### 组件规范

- 主按钮：蓝色实心，最小高度 40px；只有当前区域最重要的动作使用主按钮。
- 次按钮：Zinc 表面 + 边框；用于清空、刷新、取消归档等非主动作。
- 危险按钮：红色或危险语义；删除必须配合确认状态和影响范围说明。
- 标签：展示格式、状态、定位方式；颜色和文字同时表达含义。
- 下拉框：显示当前范围和筛选条件；切换问答范围必须明确清空临时回答和来源。
- 表格：优先保证文档名、格式、状态和更新时间；长 ID 使用短值 + 详情/复制入口，不强迫每列展示完整长值。
- 卡片：用于回答、来源、详情和状态摘要；一张卡只承载一个主要语义。
- 空状态：说明当前没有内容，并给出一个主要下一步。
- 加载状态：显示正在进行的阶段，不写“已完成”。
- 错误状态：显示脱敏错误、失败阶段和可执行的下一步。
- 抽屉/底部面板：用于移动端文档库、来源和笔记，不改变数据范围语义。

### 可访问性

- 主要文字、按钮文字和错误文字保持足够对比度；目标为 WCAG AA 级别。
- 键盘焦点使用清晰的蓝色外框，不能只依靠背景变化。
- 禁用控件降低交互能力但仍保持可读；不以灰色文字隐藏重要信息。
- 表格标题、输入框、下拉框和按钮保留明确文本标签。
- 错误、成功、加载和警告同时使用文本或图标表达。
- 触屏主要操作目标不小于 40px；移动端优先使用单列和可展开面板。
- 长文件名、章节路径、`document_id` 和 `source_locator` 必须换行、截断并提供详情，不横向撑破页面。

## 信息架构和核心流程

```text
应用外壳
├── 文档库
│   ├── 上传与索引
│   ├── 搜索、格式/状态筛选、排序
│   ├── 文档表格
│   ├── 文档详情与生命周期操作
│   └── 问答范围
├── 学习会话
│   ├── 当前会话状态
│   ├── 问答记录
│   ├── 问答输入
│   └── 回答状态
├── 来源与复习
│   ├── 来源列表和展开片段
│   ├── PDF 页码定位
│   ├── Markdown 章节/段落/行号定位
│   └── 学习笔记
└── 学习统计与报告
```

核心流程：

1. 进入应用，看到当前文档范围和文档库状态。
2. 上传 PDF/Markdown，经过校验、解析、索引，反馈 indexed、duplicate 或 failed。
3. 搜索/筛选文档只改变列表展示；选择问答范围才改变检索边界。
4. 提问后展示回答状态和来源；来源定位保留 PDF 与 Markdown 的差异。
5. 从回答和来源创建笔记；笔记继续绑定当前真实来源。
6. 新会话或切换范围时清空临时回答、来源和待保存笔记，历史数据保留。

## 核心页面规格

### 桌面端 1440×900

- 左栏：文档库和问答范围，建议宽度约 300～360px。
- 中栏：学习会话和问答，承担主要视觉权重。
- 右栏：来源与笔记，建议宽度约 320～380px。
- 顶部：产品名称、当前范围和全局状态；不增加无关业务导航。
- 问答输入靠近中栏底部，来源与笔记保持可见但不抢夺回答空间。

### 平板端 1024×768

- 中栏保持主区域；文档库收缩为可展开侧栏或上方文档选择区。
- 来源与笔记改为右侧窄面板或可展开面板，不与问答争夺固定宽度。
- 表格只保留文档名、格式、状态、更新时间和操作入口；完整详情放入详情区。

### 移动端 390×844

- 默认显示当前文档范围、问答记录和问答输入。
- 文档库进入抽屉；来源与笔记进入底部面板或可折叠区。
- 不在首屏强行展示十列文档表格；用文档卡片/关键字段 + 详情展开替代。
- 来源卡片先显示文档名、定位摘要和展开入口；展开后显示完整片段。
