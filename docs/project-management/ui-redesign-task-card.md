## 背景与问题定义

上一轮 UI 任务已经完成深色主题、Zinc 表面、蓝色主交互、响应式和状态验收，但主要是在现有 Gradio 三栏结构上进行样式适配。负责人实际体验后确认：视觉变化不足，核心问题不是颜色，而是应用外壳、组件形态和交互层级没有重设计。

当前 UI 的主要问题：

1. “文档库、学习会话、来源与复习”仍然是三个同权重并列面板，缺少主工作区和上下文区域的关系。
2. 学习会话中间区域存在大块空白，问答输入没有形成模板式的底部 Composer。
3. 文档库依赖 `gr.Dataframe` 和原始详情 JSON，长文件名、状态、`document_id` 和错误信息不适合阅读。
4. 来源使用原始 JSON 展示，PDF 页码和 Markdown 章节/段落/行号没有形成可读的来源卡片。
5. 笔记编辑、来源引用和笔记列表之间缺少上下文关系。
6. 搜索、格式、状态、排序控件以堆叠方式出现，缺少清晰的工具栏层级。
7. Gradio 默认控件可能出现白色背景、原生下拉框和不一致的边框，和深色工作台不一致。
8. 移动端主要是纵向堆叠，尚未形成抽屉、底部面板或明确的上下文切换模式。

## Figma 模板实际参考规格

以下结论来自模板节点 `1239:27621` 的只读结构和设计上下文提取，不是抽象的风格描述：

- 页面画布：1440×900，黑色全局背景。
- 顶部导航：高度约 76px，左右内边距约 40px，内容居中对齐。
- 左侧资源导航：位于 x≈30、y≈86，宽度约 200～220px；菜单项高度 42px，圆角 16px，水平内边距 10px，图标容器 30px，图标与文字间距 8px。
- 中央内容区：聊天内容宽度约 680px，保持稳定阅读宽度并居中。
- 底部输入区：高度约 68px，具有顶部边界、半透明黑色背景和模糊层；内部包含图标、文本输入和 30px 圆形发送按钮。
- 消息气泡：用户气泡 `#2F80ED`，助手气泡 `#27282A`，日期分隔条 `#18181B`；普通气泡约 16px 圆角，并用 4px 单角表达消息方向。
- 文字：模板正文约 16px、22px 行高；次要文字约 `#A1A1A9`；主文字为白色。
- 交互层级：顶部导航 → 左侧资源/空间导航 → 中央主任务区 → 底部输入区；辅助信息通过上下文区域承载，而不是和主任务区平铺。

## 设计方向

### 采用方向

“知识工作台外壳 + 模板式主任务区 + 上下文检查器”。

建议结构：

```text
应用外壳
├── 左侧空间导航
│   ├── 文档库
│   ├── 学习会话
│   └── 来源与笔记
├── 主工作区
│   ├── 当前文档/范围上下文
│   ├── 会话消息或文档库内容
│   └── 底部问答 Composer
└── 右侧上下文检查器
    ├── 来源
    ├── 笔记
    └── 文档详情
```

文档库不再固定为左侧窄栏中的一张表，而是一个独立工作区；来源、笔记和详情不再作为同权重第三栏，而是围绕当前回答或当前文档的上下文面板。

### 有意不照搬的内容

- 不复制模板品牌、Logo、Cosmo 文案或认证页面。
- 不复制模板中的 Gmail、Twitter、Home 等无关业务。
- 不直接复制模板源码、外部字体资源或商业资产。
- 不把文档学习助手强行改成纯聊天产品。
- 不改变 PDF 页码和 Markdown 章节/段落/行号来源语义。

## 目标

1. 基于 Figma 模板的实际结构规格，重新设计应用外壳和页面层级。
2. 让文档库、学习会话、来源、笔记和详情形成明确的主次关系。
3. 将文档库从原始表格改造成可读的列表/行项目/详情组合。
4. 将问答输入改造成固定底部 Composer，回答区形成消息层级和加载状态。
5. 将来源和笔记改造成上下文检查器或标签页，保持 PDF/Markdown 定位差异。
6. 在桌面、平板和移动端使用不同的布局策略，而不是只做机械堆叠。
7. 保持所有既有业务语义、数据边界、会话隔离、笔记关联和生命周期行为不变。

## 核心用户流程

### 文档学习流程

上传文档 → 文档校验 → 开始索引 → 查看文档库 → 选择问答范围 → 提问 → 阅读回答 → 展开来源 → 保存或更新笔记。

### 文档管理流程

搜索/筛选文档列表 → 打开文档详情 → 归档、恢复或重新索引 → 删除前确认 → 查看成功或失败状态。

### 会话隔离流程

切换会话或问答范围 → 清空当前回答、来源和待保存笔记 → 保留持久化历史 → 在新范围内继续提问。

## 业务语义保护

- 文档列表的视觉重组不能修改 `document_id`。
- PDF 来源继续展示页码；Markdown 来源继续展示章节、段落和行号。
- 搜索、格式筛选、状态筛选和排序只改变文档列表展示，不改变当前问答范围。
- 切换问答范围继续清空当前回答、来源和待保存笔记。
- 会话、笔记、引用、归档、删除、恢复和重新索引的服务语义保持不变。
- 完整 `document_id`、hash、索引统计和错误详情必须在详情区域可访问，不强行塞入窄屏列表。

## 风险

- Gradio 内部 DOM 和 CSS 选择器可能导致模板式组件实现脆弱。
- `gr.Dataframe`、`gr.JSON` 和 `gr.Chatbot` 的可定制性有限，可能需要在 UI 层做有限包装，而不能改变服务层。
- Figma 模板是聊天产品，文档库和生命周期操作需要业务化改造，不能直接照搬聊天页面。
- 长篇中文、来源片段、表格和完整 `document_id` 在深色界面下仍有可读性风险。
- 移动端抽屉/底部面板可能受到 Gradio 组件能力限制。
- 视觉重设计范围容易扩张到新功能，必须保持本任务非目标边界。
- Gradio 上传进度 404 独立记录，不作为本任务的验收项。
